# TalentLens AI — Professional Resume Analyzer Frontend

A responsive React/Vite interface for the existing AI Resume Analyzer backend. The application presents dedicated workspaces for candidates, recruiters, and administrators while preserving the backend as the source of truth for authentication, ATS scoring, rankings, recommendations, and persistence.

## Implemented UI

### Candidate
- Secure sign in and registration
- Candidate dashboard and recent activity
- Resume upload and job-description analysis
- ATS score, matched skills, missing skills, and recommendations
- Analysis history and detailed result view
- Profile and password update

### Recruiter
- Recruiter dashboard and operational statistics
- Batch analysis and ranking for 1–5 PDF resumes
- Job-description creation, review, deletion, and ranking actions
- Resume repository with detail and deletion controls
- Result history with recommendation details
- Profile and password update

### Administrator
- System overview with live API health, record counts, distribution, and recent activity
- User management with role filters, search, pagination, and deletion
- Global resume repository with details and deletion
- Global job-description repository with details and deletion
- Platform-wide result inspection and recommendation details
- Skills library with search, pagination, and skill creation
- Audit-log timeline with search and pagination
- Profile and password update

## Setup

```bash
npm install
npm run dev
```

The backend is expected at `http://localhost:5000` by default. To use another URL, create a `.env` file:

```env
VITE_API_URL=http://localhost:5000
```

## Production build

```bash
npm run build
npm run preview
```

## Architecture

The frontend is organized by infrastructure (`api`, `config`, `contexts`, `hooks`, `routes`), reusable presentation (`components`, `layouts`, `styles`), and role-oriented screens (`pages`). All backend calls are exposed through domain API modules that share one Axios client, and `@` resolves to `src` for stable imports.

See [REFACTORING_REPORT.md](./REFACTORING_REPORT.md) for the full file-move map, API inventory, and verification results.

The `dist` folder is generated by the production build. Rebuild it after source changes before deploying static assets.

## Backend admin account

The backend README documents the seeded administrator account. Public registration intentionally supports only candidate and recruiter roles.
